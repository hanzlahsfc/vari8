## Notes

- Harness gotcha worth flagging to other workers: `cd <worktree> && (ticker) &` backgrounds the whole `cd && ticker` list, so a compound command can silently run vitest in the **main checkout** instead of the worktree. The main checkout has a `.env` with `ENABLE_CLIENT_DASHBOARD=1`, which flips the dashboard flag gate and makes `dashboard-layout.test.ts` fail (`denied` vs `not_available`) — a false baseline failure. I verified via the vitest `RUN` banner path and re-ran confined; all baselines are genuinely green in the worktree. Used `/tmp/run-w4.sh` (cd + env export + exec vitest) for every subsequent run.
- Same architecture across the slice: `describe.skipIf(!INTEGRATION_DATABASE_URL)`, `prisma migrate deploy` + `TRUNCATE … RESTART IDENTITY CASCADE` in beforeAll, serializable transactions, Proxy/trigger fault injection (forced audit failure, injected P2002, held FOR UPDATE barriers) rather than mocks.
- `lib/checkin/instances.ts` is shared by p025b and checkin-feedback-i1 (and other lanes' files) but the exercised functions are disjoint (schedule/submit/cancel/state-projection vs feedback send/list/resolve) — not duplicates.
- p013's "schema constraints" block and p025b/p020b's constraint tests poke Prisma directly, but they prove integrity by asserting real writes **reject** — behavior of the trust boundary, unlike p008 which only reads the catalog and asserts names exist.
- p008 note: it would pass even if every service function returned undefined — nothing it imports is callable product code; its migration-time claims are covered behaviorally by p013/p025b/p020b which exercise the same constraints through writes.
- Runtime: p020b ~19–67s (heaviest; concurrency test holds real row locks — during the bite run it took ~67s because both racers failed), p025b ~16s, checkin-feedback ~14–19s, p013 ~12–16s, dashboard ~11–14s, p025a ~6–8s, p008 ~1s.
- `git status --porcelain` empty; all six production files restored via `git restore` after each bite; nothing left running.
