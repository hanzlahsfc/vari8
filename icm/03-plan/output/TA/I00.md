The owner's ~75% cut estimate is not confirmed by this slice. Every file
here is a real-PostgreSQL suite (own disposable DB, `prisma migrate deploy`
plus truncate in `beforeAll`, serializable transactions, fault injection via
proxies and triggers rather than mocks) that calls production services,
boundaries, or actions through their real signatures and asserts literal
results: row state, error codes, audit shapes, revision numbers, denial
matrices, concurrency outcomes, timezone-derived instants. That is exactly
the behavior class D11 keeps, and a browser check cannot see most of it.
Consent and health-data rules were parked per D12: no file was kept because
it tests consent.

Lead verification: I re-ran the bite check myself on 3 KEEP rows per worker
(12 of 26 bite-checked rows, script `/tmp/ta-i00-verify.sh`, logs under
`/tmp/ta-i00-w*/`). All 12 reproduced the worker's claimed failure
(i4-next-checkin 2 fail, p024 11, p014 4, p010 1, p025a-checkin-actions 1,
habits 3, client-tasks 1, mealplan-i1 5, p022 1, dashboard-layout 6,
p025a-checkin-forms 3, p013 2). Failure counts matched worker reports
exactly. Rows re-run by the lead are marked `[lead re-run: FAIL]` below.
