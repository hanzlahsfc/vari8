# PR-05 — Better Auth and /api/v1 foundation

Card `PR-05`, issue #58. Branch `beta/pr-05-auth-api`, worktree
`vari8-worktrees/pr-05-auth-api`, base `55a0f08` (post-PR-02 merge).
Decision: `icm/05-build/AUTH-DECISION.md` (Better Auth replaces Auth.js v5;
Hanzlah's invite token store is kept; reset links 60 min + single use;
refresh-token rotation deferred to the mobile issue).

## What changed

### Auth engine

- `better-auth@1.7.10` + Prisma adapter on the existing PostgreSQL schema
  (`lib/auth/server.ts`). Sessions are `session` table rows — revocation is
  row deletion; no JWT/`sessionVersion` machinery remains.
- Email+password with the repo's existing scrypt (`lib/password.ts` plugged in
  via `emailAndPassword.password.{hash,verify}`) — hashes written before the
  cutover verify unchanged.
- `bearer()` exposes the session token as `Authorization: Bearer` for API
  clients; `nextCookies()` bridges Set-Cookie into server actions.
- Rate limiting: built-in limiter, `storage: "database"` (`rate_limit` rows,
  shared across instances, survives restarts). `/sign-in/email`: 10 attempts /
  minute — the card's live proof expects the 11th rapid wrong password refused
  while the first ten still reach the credential check.
- `hooks.before` enforces repo invariants Better Auth doesn't know:
  (a) sign-in refuses non-`ACTIVE` users with the same generic
      `INVALID_EMAIL_OR_PASSWORD` failure as a wrong password;
  (b) `/sign-up/email`, `/reset-password`, `/change-password` all run the
      owner-decided policy (`>=10` chars, `>=1` digit).
- `emailAndPassword.disableSignUp: true` — no orphan users; coach self-signup
  goes through `lib/auth/signup.ts` (user + credential account + workspace +
  `WORKSPACE_OWNER` membership in one transaction).
- Password reset: `resetPasswordTokenExpiresIn: 3600` (60 min per decision),
  `verification` rows consumed atomically inside `resetCredentialPassword`
  (single use), `revokeSessionsOnPasswordReset: true`.
- Mail delivery: `lib/mail/index.ts` — one fail-closed port; `dev-file`
  adapter appends JSONL to `DEV_MAILBOX_FILE` (implicit default outside
  production; production requires an explicit `MAIL_DELIVERY_ADAPTER`).
- Inactive accounts: `lib/auth/viewer.ts` re-reads `User.status` on every
  resolution — a deactivated user's existing session stops working on the
  next request (same guarantee the old `sessionVersion` JWT gate provided).

### Schema — `db/migrations/20261020000000_pr05_better_auth/migration.sql`

Additive: `sessions`, `accounts`, `verifications` (unique `identifier`),
`rate_limit`; `users` gains `email_verified`, `image`, and
`password_hash SET DEFAULT ''` (Better Auth refuses to insert users when a
required column it doesn't know exists; `password_hash` stays as the legacy
mirror — flagged read-dead for PR-R2). Backfill: every existing `users` row
gets a `credential` account row (`providerId='credential'`, `accountId=id`)
carrying the same scrypt hash — verified end-to-end by the rewritten
`s1-a-identity` case (scratch DB: init+S1-A migrations, pre-existing user,
then the PR-05 migration: account row exists and the password verifies).

### Compatibility seam — `auth.ts`

Keeps the existing call-site contract: `auth()` returns `SessionLike`
(`{user:{id,email,name}}`), `signIn("credentials",…)` and `signOut()` for the
server actions. All ~69 existing `auth()` consumers (guards, pages, services)
are untouched. `app/api/auth/[...all]` mounts `auth.handler`; the old
`[...nextauth]` route, `auth.config.ts`, `lib/credentials.ts`,
`lib/auth/session.ts`, `lib/auth/password-reset{,-delivery}.ts` are deleted.

### /api/v1 foundation

`lib/api/v1.ts` `defineApiV1Route`: authenticate (cookie or bearer via
`getViewerFromHeaders`; bearer is rewritten into the session-cookie path
inside the auth pipeline) → Zod-validate route params + query → resolve
ACTIVE membership in ACTIVE workspace → map `MemberRole` to the D15 role →
require a non-deny `capability` scope → call exactly one service function →
typed JSON (`{error:{code}}` + 400/401/403/500). Reference route
`GET /api/v1/workspaces/:workspaceId/clients` →
`lib/workspace/roster.ts#listWorkspaceClientRoster` (keyset-paginated,
workspace-scoped).

`lib/auth/roles.ts` — the D15 capability matrix (`CAPABILITY_MATRIX`):
`WORKSPACE_OWNER→owner`, `COACH→coach`, `CLIENT→client`;
`ASSISTANT_COACH`/`SUPPORT` map to no role (deny) until the owner assigns
them capabilities. `docs/security/authorization-model.md` now documents the
shipped surface from this table.

### Surfaces

- `/signup` — coach self-signup (real form + server action); lands signed in.
- `/login`, `/reset-request`, `/reset` — rewired to the Better Auth boundary
  (`lib/auth/password-reset-boundary.ts`: non-enumerating responses, reset
  pages 404 while mail delivery is unconfigured — unchanged gate).
- Invite acceptance (`lib/workspace/invitations.ts`) still uses Hanzlah's
  `access_token` invite store; on acceptance it now also creates the
  Better Auth credential account row for the new user.
- Canvas (`frontend/`) untouched; root-app pages render and sign in as before
  (proved live, below).

## Live proof — `scripts/live-proof-pr05.mjs`

Fresh `app_pr05` (drop+create, 36 migrations applied), dev server
`next dev --port 3620` with `BETTER_AUTH_URL=http://127.0.0.1:3620`,
dev-file mailbox at `/tmp/pr05-mailbox.jsonl`. Real Chromium for the form
flows; plain `fetch` for the API matrix. **14/14 PASS**:

```
PASS  signup: coach form creates account+workspace, redirects in
PASS  sign-in: form login lands on the app
PASS  wrong password: refused with generic inline error — Invalid email or password.
PASS  sign-in: /api/auth/sign-in/email 200 + bearer token — 200 token=true
PASS  wrong password: 401 INVALID_EMAIL_OR_PASSWORD
PASS  rate limit: 10x401 then 11th 429 — 401×10,429
PASS  reset request: 200 + reset link delivered to dev mailbox
PASS  reset consume: 200
PASS  reset single-use: second consume 400 INVALID_TOKEN
PASS  reset expiry: 400 INVALID_TOKEN
PASS  password change: prior sessions revoked, fresh session works
PASS  roster bearer 200 (literal JSON) — 200 {"items":[],"nextCursor":null}
PASS  roster foreign-workspace member 403 — {"error":{"code":"forbidden"}}
PASS  roster no credentials 401 — {"error":{"code":"unauthenticated"}}
```

Behavior notes discovered live:

- Better Auth `POST` endpoints enforce Origin (CSRF) — proof requests carry
  `Origin: <base>`; a real browser always sends it.
- `change-password` with `revokeOtherSessions: true` deletes **all** session
  rows including the caller's and mints a fresh session returned in the
  response body (`token`) — the caller stays signed in on a new credential.
- A second `request-password-reset` does **not** supersede the first token;
  both remain valid for their TTL. Old-store sibling-revocation is gone; the
  card's decision (60 min + single use) doesn't require it.
- DB-backed rate buckets persist between proof runs — the script namespaces
  simulated client IPs per run.
