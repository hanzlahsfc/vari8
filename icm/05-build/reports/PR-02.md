## 3. Errors found and fixed

### E1. `npm run lint` exit 2 — FlatCompat vs flat-config-only `eslint-config-next@16`

- Symptom: `TypeError: Converting circular structure to JSON` in
  `@eslint/eslintrc` `config-validator.js` at `eslint.config.mjs:13`
  (`compat.extends("next/core-web-vitals", "next/typescript")`).
- Root cause: `eslint-config-next@16` exports flat config arrays; `FlatCompat`
  resolves them as legacy shareable configs and the validator's `JSON.stringify`
  hits the plugin object cycle. Upgrade breakage, not pre-existing (P1 §3b).
- Fix (`eslint.config.mjs`): import `eslint-config-next/core-web-vitals` and
  `eslint-config-next/typescript` directly and spread them as flat arrays;
  ignore list unchanged. `@eslint/eslintrc` devDependency removed (its only use).
  Result: lint runs, exit 0.

### E2. 11 new `react-hooks` v6 findings on pre-existing code — downgraded, not fixed

- `eslint-config-next@16` bundles `eslint-plugin-react-hooks` v6 with new
  recommended rules on. They flag render-safety patterns in app code that
  predates the upgrade. Baseline lint: 0 errors / 5 warnings. After upgrade:
  10+1 errors → all 11 as warnings now, exit 0.
- Decision: fixing these is PR-03 scope (PLAN.md PR-03: "fix all 10 P1
  react-hooks findings"; DECISIONS.md D4a lists the same rules). Changing the
  code here would break the card's "behaviour identical" constraint, and
  suppressing silently is barred by D4a — so the four rules are set to `"warn"`
  in `eslint.config.mjs` with a comment naming the PR-03 handoff. Findings stay
  visible in every lint run.
- Sites (this tree — one more `set-state-in-effect` than P1's older base):
