## What changed

Auth keeps every page, form field, name attribute, server action, route and line of copy.
Only the presentation moved onto the app's own vocabulary.

- `app/auth.css` (new, scoped to `.auth-screen`): the app panel pattern (bordered surface,
  `--radius-md`, `--space-*` scale, `--font-size-*`), input and button states, error and
  success treatments. Every value is a theme token.
- `app/{login,signup,reset,reset-request,invite}/layout.tsx` (new, 16 lines each): render the
  route inside `.auth-screen > .auth-card` and import `app/auth.css`. No page file changed, so
  no path, import or test moved.
- `app/AGENTS.md`, `docs/index/ROUTES.md`: regenerated by `npm run index` for the five new
  layouts.

Design decisions, with reasons:

1. The card reuses the existing `.workspace-list__item` / `.notice` recipe (border
   `--color-border`, radius `--radius-md`, background `--color-surface`) instead of inventing a
   panel style. Grep confirms the app never fills a button with the accent and never applies a
   shadow: the primary button is a bordered surface with an accent border, matching
   `.theme-toggle__button`, which also sets `min-height: 44px`.
2. Both themes are honoured. The app's theme is `data-theme="pro-dark|pro-white"` on `<html>`,
   set by `themes/pro-dark.css` / `pro-white.css` and the bootstrap in `app/layout.tsx`; every
   auth value resolves through `--color-*`, so the auth pages follow the toggle. An earlier
   draft imported `components/canvas/app/{globals,appearance}.css` to inherit the canvas glass
   surfaces; that was rejected and reverted because the canvas is a separate aesthetic with its
   own `data-mode`, it ignored pro-white, and importing its stylesheet into the auth bundle
   broke the production build (see gate history below).
3. Inputs use `--color-base` on the card's `--color-surface` so the field is a recessed well:
   the palette has no token lighter than `--color-border` that would read as a stroke on the
   card without competing with `--color-text-secondary`.

  form components, which are unchanged.

  copy exists for them on these pages, so nothing new was added.
- Screen reader and keyboard-only pass beyond the focus ring: the 44px targets and the existing
  `:focus-visible` rules are in place, no automated a11y run was done in this card.
- Auth integration suites were not run separately (`npm run test:integration`); `npm run test`
  is green, and no auth code changed.
