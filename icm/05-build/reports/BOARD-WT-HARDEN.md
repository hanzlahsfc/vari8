# BOARD-WT-HARDEN report

Issue #81, branch `beta/board-worktree-hardening`, PR #82 against `Vari8-Beta`.

## What changed

`icm/05-build/tools/board.py`, `ensure_worktree`:

- An existing `<path>/.git` is reused only when `git -C <path> symbolic-ref --short -q HEAD`
  returns `beta/<slug>`. A worktree on another branch, a detached HEAD, or an unreadable `.git`
  raises RuntimeError naming the path and the actual branch, so the card stays blocked and
  `release_once` exits 1.
- A failed `git worktree add -b beta/<slug>` now runs `git -C REPO branch -D beta/<slug>` to
  remove the ref it created. The cleanup only runs when the ref did not exist before the call
  (`has_branch` was false), so a pre-existing branch is never deleted.

`icm/05-build/tools/board_selftest.py`:

- New case `wt-orphan-ref`: failed `worktree add` (path blocked by a non-empty dir) must leave
  no `refs/heads/beta/c` behind.
- New case `wt-wrong-branch`: a real worktree on `beta/other` at the card path must fail closed
  (exit 1, card stays blocked, stderr names path and `beta/other`).
- `wt-dotgit` now builds a real worktree on `beta/c` instead of writing a fake `.git` file;
  its expectations are unchanged and it still passes.

`docs/index/SYMBOLS.md`: regenerated by `npm run index` (pre-existing generator drift on
`lib/appearance` and `lib/db.ts`, unrelated to this diff; committed per the pipeline footer).
