## What landed

- `lib/runtime.ts`: shared trusted-runtime contract. `classifyRuntime` trusts
  exactly `APP_ENV` (else `NODE_ENV`) equal to `development` or `test`; every
  other value, missing, malformed, staging, or production input resolves
  fail-closed. `devFlagEnabled(flag, env)` preserves exact-1 semantics and adds
  the trusted-runtime check (V3-H4-02). `consentGatesEnabled` applies the same
  contract to `ENABLE_CONSENT_GATES` (D19).
- Every exact-1 development flag gate now runs through `devFlagEnabled` and
  therefore only activates in development or test runtimes. Exported gate names
  and call-site signatures are preserved; the env parameter defaults to
  `process.env` so existing tests and callers are untouched.
- Consent and health-data gates read `ENABLE_CONSENT_GATES`, unset by default
  (D19). With the flag off, consent checks allow and skip consent reads/writes.
  With the flag on in a trusted runtime the previous enforcement path runs
  unchanged. In an untrusted runtime the flag cannot turn enforcement on
  (fail-closed).
- The four per-domain consent resolvers were merged into `lib/consent.ts`
  (F11 pure move) under their original names; the four old files are deleted.
- `lib/auth/password-reset-delivery.ts`: the empty adapter registry is inlined
  (F12). Adapter availability returns `false` and delivery is a deliberate
  no-op, which is the same observable behavior as before.
- `scripts/seed/index.ts`: ordered seed loader for `scripts/seed/*.seed.ts`.
  Refuses to run unless the runtime is development or test and refuses
  databases that are not `app_<lane>` (never `app_dev`, never a non-lane name).
- `scripts/seed/00-workspace.seed.ts`: creates the `canvas-demo` workspace,
  owner Liliana Mansfeld (`WORKSPACE_OWNER`), coach Sofia Miller (`COACH`),
  both with active memberships, and the 15 synthetic canvas client profiles.
  Emails and passwords come from environment variables only.
- `scripts/db-fresh.ts` + `npm run db:fresh`: recreates `app_<lane>` (from
  `LANE_DB` or `npm_config_lane`), runs `prisma migrate deploy`, runs the
  catalog imports when their source data is present, then runs the seed
  loader. `npm run seed:dev` runs the seed loader alone.
- `.env.example`: documents every flag the gates read, including the three
  previously missing ones (`ENABLE_CLIENT_DASHBOARD`, `ENABLE_MEAL_PLANS`,
  `ENABLE_TRAINING_PLANS`), `ENABLE_CONSENT_GATES` (unset by default), the
  runtime contract, and the seed variables.
- `docs/dev/runtime.md`: runtime classification contract, flag contract, seed
  and `db:fresh` usage.
- `vitest.config.ts` / `vitest.integration.config.ts`: test env sets
  `ENABLE_CONSENT_GATES=1` so the existing consent suites keep exercising the
  parked code until PR-T2 removes it.
- `tests/integration/p023-onboarding-submission.test.ts`: the production-env
  assertion now expects the exact-1 runtime boundary refusal
  `{ ok: false, message: "This feature is not available." }`, because the
  feature gate refuses before the consent layer is reached. Consent-layer
  assertions under a trusted runtime are unchanged.
- `icm/05-build/evidence/PR-03b-verify-3/probes/variant-mount-timing.dom.test.tsx`:
  one-line import repair for a pre-existing base typecheck break (the probe
  imported a symbol that no longer exists; now imports the current name).
- `AGENTS.md`, `lib/AGENTS.md`, `scripts/AGENTS.md`, `docs/index/*`: generated
  index guidance blocks, regenerated by `npm run index` / `next dev`.

   modules; zero code imports remain.

   no literals in `scripts/seed/` or `scripts/db-fresh.ts`.
5. db:fresh brittleness (minor): failure now prints a remediation note
   telling the operator the DB may be partially populated and that a re-run
   recreates it from scratch.
6. Scope: `db/` and `docs/STATUS.md` untouched (diff path sweep empty).

## Limitations and blockers

1. `npm run format:check` fails on the base itself: `f02a6d6` reports the same
   97-file drift set (verified byte-identical between base and this branch).
   Every flagged file is `icm/` content, generated metadata, or config that
   predates this card; this PR adds zero new drift (the one touched file,
   `tests/unit/checkin-instances.test.ts`, was reformatted in `029fa91`). A
   repo-wide `prettier --write` sweep would touch 97 unrelated files and is
   left for the driver to land on `Vari8-Beta` first if desired.
   `verify-local.sh` therefore exits 1 at `format check` before reaching the
   remaining steps; every step after it was run manually and is green (table
   above).
2. The Playwright `webServer` config runs `npm run build && npm run start`
   with a 180s timeout; a cold root build exceeds that on this machine. The
   specs were run against the already-built production server on `:3000`
   (same env contract as the gate: `APP_ENV=test`, `DATABASE_URL=app_pr04`),
   which is what `reuseExistingServer` exists for. Under CI the same timeout
   risk applies on slower machines.
3. Catalog imports in `db:fresh` skip cleanly when the source data directories
   are absent (none exist on this machine). When sources are present the
   existing `import:nutrition` / `import:exercise` scripts run unchanged.

4. `next dev` auto-appends a Next.js guidance block to root `AGENTS.md`; it
   was committed as generated content to keep the tree clean.
5. Node warn: runtime is v26.8.2, target is 24 (D5). Recorded, not certified.
6. The 6 skipped password-reset e2e specs are skipped by design: they cover
   the delivery-on path, and delivery stays a deliberate no-op (F12).
