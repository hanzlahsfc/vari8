# CANVAS-HYDRATION report

Issue #70, branch `beta/canvas-hydration-fix`, PR #84 against `Vari8-Beta`.

## What changed

New `frontend/src/lib/reduced-motion.ts`: `useReducedMotion(): boolean` built on
`useSyncExternalStore`. The server snapshot and the client's first (hydration)
read are both `false`, so SSR HTML and the hydration render always agree. The
real `matchMedia("(prefers-reduced-motion)")` value is applied in an effect
after mount, with a live change listener. Drop-in compatible with the motion
hook: every call site used plain truthiness on a boolean.

All 17 `useReducedMotion` call sites under `frontend/src/` now import from the
shared hook instead of `motion/react`. This is the single seam every
reduced-motion-gated prop flows through, including the `eg-segment` nav's
`whileTap`, so the fix is at the shared render path, not per button.

`docs/index/SYMBOLS.md`: regenerated by `npm run index`; `index:check` exit 0.

## Root cause

framer-motion's `useReducedMotion()` lazily calls `initPrefersReducedMotion()`
during render (`framer-motion/dist/es/utils/reduced-motion/use-reduced-motion.mjs`).
On the server it is a no-op and the ref stays `null` (falsy). On the client it
reads `window.matchMedia("(prefers-reduced-motion)")` synchronously, so the
hydration render computes a different value than the server when the device
requests reduced motion.

In `frontend/src/components/ethereal/coaching-app.tsx` the five `eg-segment`
`motion.button`s use `whileTap={reduceMotion ? undefined : { scale: 0.975 }}`.
framer-motion's `useHTMLProps` emits `tabIndex={0}` only when `onTap`,
`onTapStart`, or `whileTap` is present
(`framer-motion/dist/es/render/html/use-props.mjs`). Result under
`prefers-reduced-motion: reduce`: SSR emits `tabindex="0"`, the client
hydration render omits it, and React reports a hydration mismatch on all five
buttons.

The issue names `/coach`, but `eg-segment` is the Ethereal studio nav rendered
by `/` and `/ethereal`. `/coach` shows the reduced-motion notice
(`coach/ui.tsx:288`, `Transition`) but no hydration error: its tree sits behind
a `useSearchParams` Suspense bailout and is never hydrated against SSR DOM.
The mismatch was reproduced exactly on `/` and `/ethereal`.
