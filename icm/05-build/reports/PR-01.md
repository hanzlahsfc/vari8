## Decisions made in this PR (for review)

1. **Webpack instead of Turbopack for the root app.** Measured: the Turbopack build renders the Ethereal studio
   screens 1 to 2 colour levels off the baseline (s10-appearance@1440: 35382 pixels, all within 2/255); the
   webpack build of the same tree matches bit for bit. The canvas was built with webpack. Backend build, unit,
   integration and e2e all pass on webpack.
2. **Owner-ruled parity deltas** (`RULED` in `tools/parity/compare.mjs`). D32 lists truth-text exceptions only;
   these two come from the card itself. A ruled element leaves the geometry diff and its boxes (padded 21 px, three
   sigma of the dialog's 7 px backdrop blur, which spreads the label change 14 px under an open dialog) leave the
   pixel diff. Everything else, including any neighbour moving, still fails.
   - D18: the account role reads `Owner` for the seed owner where the baseline says `Coach` (every coach screen at 1440).
   - S11-03: `Sign out` in the preferences dialog (s11-preferences at both widths).
3. **Who may open the canvas.** The card says "behind the existing session". I also require an ACTIVE owner or
   coach membership in an ACTIVE workspace, because the account block can only show `Owner` or `Coach` (D18) and
   the D15 matrix denies clients `roster.read`. A client gets the 403 page on `/`, `/coach` and `/ethereal`.
   With several staff workspaces the first by name is shown (no switcher, O15). Owner, please confirm.
4. **Sign-out placement.** In the dialog footer, visually left of `Done` (`order: -1`), so `Done` keeps its place
   and DOM path. Keyboard order is `Done` then `Sign out`.
