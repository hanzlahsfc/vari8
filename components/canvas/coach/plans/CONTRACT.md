# Individual plans integration contract

Lead owns model.ts, store.tsx, templates.tsx, check-ins.tsx, client-preview.tsx and plans/domain.ts, plans/types.ts, plans/workspace.tsx. Do not edit these concurrently.
CoachClient.plans?: ClientPlans (from plans/types.ts); use client.plans ?? emptyClientPlans(). Legacy client.plan retained read-only as legacy summary. No independent storage.
Routes: section=clients&client=ID&plan=nutrition|training|setup|goals|habits, optional review=SUBMISSION, tab=Plans. Lead owns route parsing/outer editor mounting. clients.tsx worker removes old PlanDialog export and mounting (lead removes check-in usage).
NutritionEditor export from plans/nutrition/editor.tsx: props { value: MealPlan; onChange: (value: MealPlan)=>void }; IifymEditor same file, props { value: IifymPlan; onChange:(value:IifymPlan)=>void }. Lead renders name/date/lifecycle toolbar; editor may render name/date too if useful. Lead creates empty client-specific values; no seeding actual clients. Editor controlled state, no persistence/provider/controllers. Own plans/nutrition/** only.
TrainingEditor export from plans/training/editor.tsx: props {value: TrainingPlan; onChange:(value:TrainingPlan)=>void; configuration: Variant}. Own plans/training/** only. Types/resolveTrainingWeek/setTrainingWeek in ../types.ts are stable. Lead renders lifecycle toolbar and outer preview. Training may export TrainingPrescription({value,week?,configuration}) for readonly preview.
Profile worker owns clients.tsx and plans/setup-ui.tsx / setup-ui.css only. Export ClientPlansSummary({client}) and ClientGoalsEditor({client}), ClientHabitsEditor({client}); use CoachProvider setState for explicit saves to client.plans.goals / client.habits; return/back outer handled by lead. Summary uses lifecycleStatus from plans/domain.ts (lead building): lifecycleStatus(lifecycle) => string; applicablePlan(lifecycle,date) => T|undefined; current date TODAY from model. All client content stays independent.
Nutrition presentation is templateSetup(client.assignment.snapshot, client.assignment.variantId).nutrition; preserve both forms when switching. Configuration enables views Nutrition / Training Program and habits boolean; Goals available for configured non-nutrition numeric fields.
Lifecycle: draft separate from immutable active {id,content,activatedAt}; history retains previous versions on activation. Save persists incomplete without publishing, activate independently validates module and records review origin activation. Active preview date selects latest applicable version startDate<=date, preserving previous before future version. Archiving draft does not touch active; explicit archive active marks date cutoff. No history entries on draft saves. Outer workspace uses guard for unsaved work.
